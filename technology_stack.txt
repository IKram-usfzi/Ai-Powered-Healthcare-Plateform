# Topic 7 — Standard Open-Source Technology Stack

This section tells us **which technologies are recommended for building the GlobalCare platform**.

Don't try to memorize this as one huge list. 😄
Understand **what job each technology does**.

Think of the complete system like a building:

```text
                GLOBALCARE PLATFORM
                       │
        ┌──────────────┼──────────────┐
        ↓              ↓              ↓
     Frontend       Backend        Database
      React         FastAPI       PostgreSQL
        │              │              │
        └──────────────┼──────────────┘
                       ↓
                AI / Analytics
                       │
        ┌──────────────┼──────────────┐
        ↓              ↓              ↓
    Scikit-learn     Pandas         NumPy
        │
        ↓
   Monitoring / Operations
        │
 Docker + Prometheus + Grafana
        │
        ↓
 Security + Authentication
        │
 Trivy + OPA + JWT
```

Let's understand every part.

The main programming language is:

> **Python**

Python can be used for:

* Backend development

* Data processing
* Automation
* APIs
* Healthcare analytics

So Python becomes one of the central technologies in the project.

```text
Python
 ├── FastAPI
 ├── Scikit-learn

 ├── NumPy

```

# 2. Backend — FastAPI

The backend is the **logic layer** of our application.

We're using:

> **FastAPI**

Think of FastAPI as the middle layer between the frontend and the database.

```text
React
  ↓
FastAPI
  ↓
PostgreSQL
```

For example:

```text
GET /patients
```

FastAPI receives the request.

It talks to PostgreSQL.

Then returns the patient data to React.

```text
React
 ↓
GET /patients
 ↓
FastAPI
 ↓
PostgreSQL
 ↓
Patient Data
 ↓
FastAPI
 ↓
React
```

FastAPI will also be important for:

* Authentication
* Patient APIs
* Appointment APIs
* Monitoring APIs
* AI APIs

---

```text
┌─────────────────────────────┐
│      GLOBALCARE             │
```

```text
User
```

So remember:

> **React = frontend / user interface**

> **FastAPI = backend / business logic and APIs**

For example:

```text
Patients

AI Predictions
```

Conceptually:

```text
FastAPI
   ↓
PostgreSQL
```

```text

   ↓
```

---

# 5. Cache — Redis

Redis is an **in-memory data store**.

It's much faster than repeatedly querying the database for certain types of temporary/frequently accessed information.

For example:

```text
User Request
     ↓
Redis Cache
     ↓
Data available?
   /       \
 YES       NO
 ↓          ↓
Return    PostgreSQL
             ↓
           Redis
             ↓
           Return
```

We could use Redis for things such as:

* Frequently accessed dashboard data
* Temporary session/state information
* Rate limiting
* Short-lived cached results

Important:

> **Redis does not replace PostgreSQL.**

Think:

```text
PostgreSQL = Primary persistent database

Redis = Fast temporary/cache layer
```

# 6. Healthcare Standards

This section is slightly different.

The project gives three healthcare-related technologies:

### HAPI FHIR Server

FHIR stands for:

> **Fast Healthcare Interoperability Resources**

FHIR is a healthcare interoperability standard.

It defines ways of representing and exchanging healthcare information.

For example:

```text
Patient
Observation
Appointment
Practitioner
Encounter
```

So FHIR helps different healthcare systems communicate using standardized healthcare resources.


* Load CSV files

* Filter records

* Analyze datasets

> **Pandas = working with structured datasets**

# 15. Containerisation — Docker

Docker packages applications into containers.

For example:

```text
Docker
 ├── React Container
 ├── FastAPI Container
 ├── PostgreSQL Container
 ├── Redis Container
 └── Monitoring Containers
```

A container provides a consistent environment for an application.

Instead of installing everything directly onto your laptop:

```text
Laptop
 ├── Python
 ├── PostgreSQL
 ├── Redis
 ├── Node
 └── dependencies...
```

we can package components into containers.

---

# 16. Docker Compose

We have multiple containers.

How do we run them together?

> **Docker Compose**

For example:

```text
docker-compose.yml

services:
  frontend
  backend
  postgres
  redis
```

Then:

```text
Docker Compose
      ↓
Starts all required services
```

This is particularly appropriate because your project explicitly requires a **Docker Compose deployment**.

```text
Configuration
```

For example:

```text

     ↓
```

# 21. Security — Open Policy Agent

Open Policy Agent, or **OPA**, is a policy engine.

It allows us to define rules.

For example:

```text
Policy:
Only authorized users
can access patient information.
```

Conceptually:

```text
Request
   ↓
OPA Policy
   ↓
Allowed / Denied
```

This introduces **policy-based security** into the architecture.

---

# 22. Authentication — FastAPI JWT Authentication

JWT means:

> **JSON Web Token**

It can be used to authenticate users.

For example:

```text
User
 ↓
Login
 ↓
FastAPI
 ↓
Verify Credentials
 ↓
JWT Token
 ↓
User makes API request
 ↓
Token verified
 ↓
Access granted
```

This helps protect APIs.

Different users could eventually have different roles:

```text
Patient
Doctor
Administrator
Executive
```

And their access should be controlled accordingly.

# ⭐ How to Explain the Stack in Your Viva

If the examiner asks:

> **"Why did you select this technology stack?"**

A professional answer would be:

> **"I selected a lightweight open-source technology stack that aligns with the project's functional requirements and laptop resource constraints. Python provides a common foundation for backend development, data processing, and machine learning. FastAPI provides the REST API layer, React provides the user interface, and PostgreSQL provides persistent relational storage. Docker and Docker Compose provide reproducible deployment of the platform's services. Scikit-learn, Pandas, and NumPy support lightweight AI and healthcare analytics, while Prometheus and Grafana provide observability. Security is supported through JWT authentication, Trivy vulnerability scanning, and policy enforcement using OPA. Git, GitHub, and Markdown/MkDocs support professional development and documentation."**

That's the **big-picture answer**.

You don't need to say every technology unless the examiner asks.
